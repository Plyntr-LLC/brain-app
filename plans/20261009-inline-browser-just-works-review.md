I would not ship this plan unchanged. Several checks pass while a wrong implementation still opens Chrome, keeps streaming, or drops real input.

1. **The `open` allow-list still opens ordinary pages, and the shim check never tries one.** The pattern is an unanchored substring: `saml` matches `sample`, `/device` matches `/devices`, `sso` matches `association`, `callback` matches a normal query. Step 1 only requires `https://example.com` to be refused and two login URLs to reach `BRAIN_OPEN_BIN`. `open -a "Google Chrome" https://example.com` is also untested, so a shim that inspects only the first argument passes. Anchor the pass-through to real CLI login URLs, and require refusal for those near-misses and for `open -a "Google Chrome" https://example.com`.

2. **The wa.cjs guard is only proven for `status` and `list`.** In `code/whatsapp/wa.cjs`, `link`, `status`, `read`, `voices`, `reply`, `send`, `batch`, and `stay` all launch Chrome inside `openContext` (`chromium.launchPersistentContext` with `channel: 'chrome'`). `self-test` does not, and there is no `--window` flag today. A guard wrapped only around `status` exits 2 on the tested command and still launches Chrome for `read` or `reply`. An always-on guard also passes, because the no-`BRAIN_CHAT` case only runs `list`, which is allowed in both modes. Run every launching command under `BRAIN_CHAT=1` and require exit 2, the guard sentence, and no new Chrome or Chromium pid within 2 seconds. Require `self-test` to print `ok` with `BRAIN_CHAT=1`. Prove `--window` skips the guard, and prove one launching command without `BRAIN_CHAT` gets past it, by stubbing `launchPersistentContext` so Joe's Chrome never opens.

3. **The Chrome oracle can launch Chrome and still miss Playwright.** `tell application "Google Chrome"` starts Chrome when it is not running, which changes the window and tab counts the check is holding still. wa.cjs falls back to Playwright's Chromium, and H3 names Playwright, but the oracle is only Google Chrome's windows, tabs, and main pid. Keep the existing `pgrep` pid snapshot, include Chromium and "Google Chrome for Testing", and do not AppleScript an app that is not already running.

4. **`BRAIN_CHAT` on the chat Grok leader also covers Show terminal, and the leak check cannot see that.** `pty.ts` attaches Show terminal's Grok TUI to the same leader (`grokLeaderLive()` and `grokLeaderSocket()`), and this plan says Grok runs shell commands in that leader. Behavior 1 puts the shim and `BRAIN_CHAT` on that leader. Behavior 2 says the terminal keeps today's `open` and wa.cjs. Those conflict, and step 4 only reads the env object Desk's runner and Factory pass in, and only for the variable, not the shim directory on `PATH`. State which Grok is blocked. Assert `ptyEnv()` has neither `BRAIN_CHAT` nor the chat-shim directory. Assert the same for Factory and Desk `PATH`. If Show terminal Grok is supposed to keep `open`, the leader env is the wrong place for the shim, and a command through that TUI has to reach `/usr/bin/open`.

5. **H7 is tested by calling `watch` and `unwatch` from the harness, not by the picture leaving wide.** A renderer that subscribes on wide and never unsubscribes still passes step 6 and `browser-live`. So does a 15 fps `capturePage` loop on a static page, and a WhatsApp step that treats any later frame as the new page. `DeskPane` is on the file list for the same stream and the same input, but nothing mounts it: the desk picture stays on a 1.5 s poll (`DeskPane.tsx` interval is fixed), and `shared-browser.tsx` only checks a click, a key, and a wheel. Require a frame that still matches the previous page to fail the WhatsApp step; require no second frame for about a second on a quiet page; in `browser-live`, leave wide and mark the tab inactive and require `unwatch`; mount the desk picture and require the same pointer, key, and frame events there.

6. **H8 never crosses the real renderer with the gestures that break.** Step 7 calls main-side functions. `browser-live` dispatches events at a stub `window.brain` and does not require the image to be laid out at a size other than 1100×800, so unmapped coordinates still count as mapped. Check C, the only full path, is one click, the letters `hi`, and Enter. That passes if the preload drops `button`, `clickCount`, or the edit command, if the default macOS Edit menu eats Cmd+V (this app never calls `setApplicationMenu`), or if a native drag on the `<img>` steals the gesture. In the packed check, use a picture box that is not 1100×800 and send a real drag, a real double-click, and a real Cmd+V through the picture. Require the selection, the word, and the clipboard text on the fixture page.

7. **The packed launch turns auto-update on, and the afterward check cannot see it.** `startAutoUpdate` runs for every packaged app, eight seconds later, with `autoDownload` and `autoInstallOnAppQuit` (`src/main/update.ts`). A chat turn lasts longer than that, and a normal quit is when that install runs. `update.ts` is not in the file list. The post-check is the running `/Applications/Brain.app` pid and the Grok leader socket, which both stay put while ShipIt replaces the bundle. Skip updates for this launch, and after quit require the Applications executable mtime, the Agency Brain config mtime, and that brain's git HEAD to be unchanged.

8. **The Windows check restates `socketPath` and never looks at `listen`.** `startBrowserBridge` today builds `browser-<pid>.sock`, then `sweep`s and `chmod`s it. A correct helper with that listen path left in place passes step 8 and fails on Windows. On this Mac, assert the address the running bridge listens on equals `socketPath(process.platform, dir, pid)`. For a win32 argument, require the `\\.\pipe\brain-browser-<pid>-<hex>` path, and require that branch not to `chmod` or sweep socket files.

REJECT
