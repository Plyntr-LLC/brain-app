# Brain's browser, phase B1: everyday controls

Joe 2026-10-09: "i want this browser to have full functionality." Phase A moved Brain to Electron 44 (`plans/20261009-electron-44.md`). B1 adds the controls a person uses every day. B2 (popups as tabs, camera/mic/location/notification asks, Touch ID passkeys) is its own plan.

Working preference 13: Joe asked for these controls. The picture, Hide, the size buttons and the dock keep their places; the new controls are added to the same button row under the picture, after the sizes.

## Today

- The picture has Hide plus Small/Wide/Large. Moving between pages is only possible through the AI or a bare-address send.
- Every page is muted (`wc.setAudioMuted(true)` in `desk/inapp.ts`).
- A file input on a page opens the macOS file picker on a hidden window, so nobody sees it. Probe (Electron 37, same CDP): `Page.setInterceptFileChooserDialog` reports `Page.fileChooserOpened` with the input's `backendNodeId`, and `DOM.setFileInputFiles` fills it (the page read the file's name and size).
- A right-click in the picture reaches the page (`BrowserPicture` sends button `right`), and Electron emits `context-menu` with the link, selection and editable state (probed on 44), but Brain shows nothing.
- Cmd+P in the picture stays Brain's. Downloads save to Downloads silently.

## 1. Behavior when done

1. Navigation row (chat picture, every size except the note): after the size buttons come Back, Forward, Reload, and an address field showing the page's current address. Back and Forward are disabled when the page has no history that way. Enter in the field opens what was typed: a full address as is, `example.com` as `https://example.com`, anything else as a Google search. It goes through the same path as a bare-address send (`goTo` for that chat), so a WhatsApp address still goes to its WhatsApp window and any other address typed in a chat that is showing WhatsApp loads in that chat's own window. Only `http` and `https` are ever loaded from the field. Back, Forward and Reload act on the page the chat is showing, in that window's lane. On a WhatsApp window (`wa` or `wa:*`, shared by every chat that shows it) Back and Forward are disabled and refused if sent, so no chat can move the shared window off WhatsApp; Reload is allowed.
2. File uploads: every page Brain opens intercepts its file chooser. When a page asks for a file (the person clicked an upload control in the picture, or the AI clicked one), Brain opens a normal macOS Open panel over Brain's window (single or multiple files, as the page asked), and the files the person picks are put into that page's input (the `backendNodeId` and window that asked). Cancel puts nothing. The AI cannot supply file paths; only the person picks. One panel at a time for the whole app: asks from other pages wait their turn; a page that asks again while its own ask is open or waiting is refused (nothing opens), so a page cannot stack panels. Folder pickers (`webkitdirectory`) are out of scope this phase (backlog).
3. Sound: a page plays sound while its picture is live on screen (wide or large, in the tab on screen), and is muted otherwise. Two chats watching one WhatsApp window: sound while either watches.
4. Right-click menu: a right-click in a wide or large picture opens a native menu at the mouse, built from what was under it: Back, Forward, Reload (Back and Forward left out on a WhatsApp window); on a link: Copy link address, Open link in your browser; on a selection: Copy; in an editable field: Cut, Copy, Paste, Select all; on an image: Copy image address; always: Print to PDF, Open page in your browser. "Open ... in your browser" uses the system's default browser (the person chose it, so it is the person asking), and only for `http`, `https` and `mailto` addresses: for any other scheme (`file:`, `javascript:`, custom app schemes) the item is left out and `shell.openExternal` is never called. The menu is built by a plain function from the context-menu params and the window state, and every item acts on the window the right-click came from. A small picture opens no menu.
5. Print: Cmd+P on a wide or large picture, or Print to PDF in the menu, saves the page as a PDF in Downloads and opens it, so it can be printed from Preview. The name is the page title with `/ \ :` and control characters replaced by `-`, leading dots and spaces trimmed, cut at 80 characters, `Page` when nothing is left, then `.pdf`, a new name when one exists. Cmd+P never reaches the page as a key. A page's own `window.print()` is replaced at document start through the debugger, so no invisible print dialog opens and the page keeps running. It makes the same PDF only while that window's picture is live (wide or large, in the tab on screen, the same state that turns sound on), and at most one per window: a call while that window's PDF is being written, or within 10 seconds after, does nothing. Otherwise the call does nothing and returns at once, so a page nobody watches, or a page calling `print()` in a loop, cannot fill Downloads or keep opening Preview.
6. Downloads: when a download from a page finishes, every chat whose picture is showing the window it came from (one chat for its own window; each chat showing a shared WhatsApp window) shows one line under the picture: the file name, Open, and Show in Finder. An interrupted or cancelled download says it did not finish.
7. The agent's tools are unchanged except `browser_open`'s text gains one sentence: if a page asks for a file, Brain shows a file picker to the person.

## 2. How this can fail

F1. Back/Forward/Reload act on another chat's page, or on the chat's own window while it is showing WhatsApp (or the reverse), or run in the middle of an AI step on that window.
F2. The address field opens a typed WhatsApp address on the chat's own window (a second WhatsApp session), or sends `javascript:`, `file:` or other non-web schemes to the page.
F3. A file chooser stays invisible (not intercepted), or files are put into a different input, page or chat; or cancel leaves the page stuck; or the AI can set a path itself.
F4. Sound plays from pages nobody is watching, or stays muted while the person watches.
F5. The menu acts on the wrong page, or "Paste" types into the composer instead of the page.
F6. Print saves an empty or wrong-page PDF, or overwrites an existing file.
F7. A download note shows in the wrong chat, or for a download that failed, or never shows.
F8. The new row moves or replaces Hide, the sizes or the dock; or it shows on the note.
F9. (review r1 #1) "Open in your browser" hands a non-web address (`file:`, `javascript:`, a custom app scheme) to the system.
F10. (review r1 #2) Back or Forward from one chat moves a shared WhatsApp window off WhatsApp for every chat.
F11. (review r1 #5) Two file asks at once, or a page asking again, open stacked panels or put files into the wrong input.
F12. (review r1 #6) A page title makes a bad PDF name, or a page's own `window.print()` opens an invisible dialog or hangs the page, or (review r2) a page's own `print()` writes PDFs and opens Preview while nobody watches it, or many times in a row.
F13. (review r1 #7) Sound stays on in a window the chat left, or off in the one it moved to.
F14. (diff review r3 #1) A page closed while its file ask waits or is open jams the one-at-a-time panel queue for the whole app. The queue keys on the window id read when the ask is made. Check 3c.
F15. (diff review r3 #2) An enabled debugger Runtime domain marks Brain as automated to bot checks. The replaced `print()` speaks through the console (`console-message`), not a binding, so only `Emulation`, `Page` and `DOM` are used.
F16. (diff review r3 #4-#7) The Open panel names the site that asks, and stands alone when Brain's window is hidden. The address field searches anything with spaces and opens `localhost:3000` and bare IPs over http. The 10 s cooldown applies to the page's own `print()` only, not to a person's Print to PDF. At most 200 download ids are kept in main and 5 lines under a picture.
Backlog (review r3 #3): a page can still call `print()` on a fresh iframe's window. The harm stays inside that page (it can hang itself).

## 3. End-to-end check (medium case) and its artifact

`scripts/check-browser-controls.ts` runs the real main modules under Electron 44 (shared browser, in-app launch, the browser IPC handlers, the bridge with the real browser-mcp.cjs) with a temp userData and a local http fixture: `/a` (heading A, link to `/b`, an upload input `#one`, a multiple-file input `#many`, a "Download" link to a file, a contenteditable box, an `<audio>` that reports `play` and its `muted` state to the server), `/b` (heading B), `/c`. Recorded: what the page reports to the server, what main sends to the window, the dialog calls (Electron's `dialog.showOpenDialog` is replaced by a recorder that returns chosen paths or cancel, and can hold an answer), `shell.openPath`/`openExternal` (recorders), and the menus (`Menu.buildFromTemplate` and `Menu.prototype.popup` are replaced before the app modules load, so the check reads each template and calls an item's `click`). Fixtures also serve `/print` (title `a/b: c`, calls `window.print()` then sets `after-print` in the page), `/links` (an http link, a `file:///Applications/Calculator.app` link, a `myapp://x` link), `/broken` (download headers, half the body, then the socket is destroyed), and two upload pages. Artifact `plans/20261009-browser-controls-check.txt`.

1. Navigation: chat A opens `/a`, goes to `/b` by the address field handler, then Back shows A and Forward shows B (headings read from the page); Reload re-requests `/b` (the server sees a second GET). The face for A reports `canGoBack` true on B and `canGoForward` false. Chat B, on `/c`, is untouched by all of it (F1). A Back sent while a held AI step owns A's window waits for it (F1).
1b. Shared WhatsApp (F10): chats A and B both show the stand-in WhatsApp (the accounts check's `protocol.handle` stand-in) after A visited `/a` there first; A's face reports Back and Forward unavailable; a Back sent for A is refused and B's page (and the window's URL) stays on web.whatsapp.com; Reload for A reloads that window (the stand-in sees a second request) and B still shows WhatsApp. An address typed in A while it shows WhatsApp (`/c`) loads in A's own window; the WhatsApp window's URL is unchanged.
2. Address field: `example.test` opens `https://example.test` (the fixture maps it), plain words open a Google search URL (recorded, not loaded), `javascript:alert(1)`, `file:///etc/hosts` and `myapp://x` open nothing (F2). `web.whatsapp.com` from chat A lands in the shared WhatsApp window, not A's own (F2).
3. Upload: a real picture click on `#one` makes exactly one `showOpenDialog` call, single-file, attached to the Brain window; returning `/tmp/x/one.txt` puts that file in `#one` (the page reads name and size) and nothing in `#many`. A click on `#many` asks for multiple and both chosen files land. Cancel leaves the inputs as they were and the page still answers a read (F3). An AI `browser_click` on the upload control opens the same dialog for the person; no tool accepts a path (tools/list has no such parameter) (F3).
3b. Asks at once (F11): with the recorder holding the first answer, chat A's page asks (`#one`), then chat B's page asks (its own upload page), then A's page asks again: there is one open dialog call; A's second ask is refused (no extra call); B's ask opens only after A's is answered; A's file lands in A's `#one` and B's file in B's input, never crossed.
4. Sound: the fixture's audio element plays muted while A's picture is small; after `browser:watch(A, true)` it reports unmuted; after `watch(A, false)` muted again; with chat B also watching the WhatsApp window, stopping A's watch does not mute WhatsApp (F4). While A's watch is on, A moves to the WhatsApp window and back to `/a`: each time the window it left reports muted and the one it moved to reports unmuted (F13).
5. Menu: a right-click at a link's point opens a menu whose items include Copy link address with that link; choosing it puts the link on the clipboard. A right-click in the contenteditable then Paste puts the clipboard text into the page's box, not the composer (F5). Copy on a selection copies it. Chat B right-clicks its own page and chooses Reload: B's page reloads (the server sees B's request) and A's does not (F5). On `/links`: the http link's menu has Open link in your browser and choosing it calls `openExternal` with that URL; the `file:` and `myapp:` links' menus have no such item, and `openExternal` is never called with them; on a `file:` page itself, Open page in your browser is absent (F9). A right-click on a small picture builds no menu (F8).
6. Print: Cmd+P on A writes `A.pdf` in the temp Downloads, over 1 KB and starting `%PDF`, and calls `shell.openPath` with it; a second print writes `A (2).pdf` (F6). The page never saw a `p` key event (its keydown log is empty). `/print` (title `a/b: c`) calls `print()` from a button: in chat A while its picture is small, nothing is written, `openPath` is not called, and the page shows `after-print`; with A's picture live, `a-b- c.pdf` is written, `openPath` is called once, the page shows `after-print`, and no print dialog was asked for. With A live, `/print?loop` calls `print()` every 100 ms for 3 s: exactly one PDF is written, `openPath` is called once, and the page's counter shows it kept running (F12).
7. Downloads: clicking Download in chat A's page sends one `browser:download` event for chat A with the name and state `completed`; chat B gets none; `/broken` reports state `interrupted` to chat A (F7). A download started in the stand-in WhatsApp window while chats A and B both show it reaches both A and B, and chat C (on `/c`) gets none.
8. Render (`render-ui browser-controls`, real ChatPane): the row reads Hide, the two other sizes, Back, Forward, Reload, then the address field, in that order, in small, wide and large; the note shows none of it; Back is disabled when the face says `canGoBack` false; Enter in the field calls the go handler once with the typed text; a download event shows the name with Open and Show in Finder under the picture of that chat only (F8). A right-click on the small picture sends nothing to main, and Cmd+P on a wide picture calls print and sends no key to the page (F8).
