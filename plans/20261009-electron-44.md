# Electron 37 to 44 (phase A of the full in-app browser)

Joe 2026-10-09: "i want this browser to have full functionality so get the updates or whatever we need to make this happen." Phase A is the upgrade alone, so any regression is the upgrade's. Phase B (full browser on 44: Touch ID passkeys, popups as tabs, uploads, sound, navigation, permission asks, context menu, print) is its own plan.

## Why

- Brain is on Electron 37.10.3. Electron supports the latest three majors (42, 43, 44); 37 gets no security fixes.
- `app.configureWebAuthn` (Touch ID platform authenticator) and the `select-webauthn-account` session event exist from 41 (checked in 44.7.0's `electron.d.ts`). Phase B needs them.

## What changes between 37 and 44 that touches Brain (from the official breaking-changes list, checked against this repo)

- 44: the main-process `clipboard` methods return Promises. Brain calls `clipboard.readText()` synchronously in `src/main/bring-front.ts` (`clipOrgLogin`, `watchClipboardOrg`). No renderer or preload clipboard use.
- 44: macOS 13 or later only. 42: macOS notifications use UNNotification (Brain shows none from main). 43: `NativeImage.toBitmap()` normalizes to sRGB (only check scripts read bitmaps). 42: offscreen `deviceScaleFactor` defaults to 1 (inapp.ts already resizes every capture to 1100x800). 42: the `electron` package downloads its binary on first run, not in postinstall. 39: shared-texture OSR paint changed (Brain does not use shared textures).
- `node-pty` is a native module; it must be rebuilt for Electron 44's ABI (dev: `@electron/rebuild`; pack: electron-builder rebuilds).

## 1. Behavior when done

1. `package.json` and the lockfile pin `electron` 44.7.0. Dev, checks and the packed app run on it.
2. `clipOrgLogin` and `watchClipboardOrg` await the clipboard; `notifySetupBack` and the `setup:clipOrg` handler await `clipOrgLogin`. A copied GitHub org name is still found.
3. `node-pty` works in dev and in the packed app.
4. Everything that passed on 37 passes on 44 unchanged: no check is edited to pass, except where an Electron API itself changed (named in the diff review).
5. The packed app signs, notarizes, passes Gatekeeper, and auto-updates from 0.1.137.
6. (review r1 #1, corrected by diff review r1 #1) `electron-builder.yml` sets `mac.minimumSystemVersion: "13.0"` (the app's own macOS floor). `scripts/sync-mac-update-yml.cjs` writes `minimumSystemVersion: 22.0.0` into `latest-mac.yml`: electron-updater compares `os.release()`, the Darwin kernel version, with semver, so the yml carries Darwin (macOS 13 = Darwin 22, derived from the builder config). The first version wrote `13.0`, which is not semver: the compare threw and every Mac, macOS 12 included, would have been offered the build. electron-updater on a Mac below 13 now skips the update instead of installing a build that cannot start.
7. (review r1 #2) Release order: publish as a GitHub prerelease first; run the update checks below against the prerelease's own downloaded files; promote to Latest only after they pass. The installed 0.1.137 cannot be pointed at a prerelease: `src/main/update.ts` hard-codes the github provider with prereleases off, and the feed cannot be changed without changing the signed old app. What Squirrel.Mac checks when a running Brain applies an update is that the new bundle satisfies the running app's designated requirement, so that is checked against the installed Brain before Latest. An update that fails to apply leaves the person on the old version (it does not replace the app), which bounds the remaining risk.

## 2. How this can fail

F1. `node-pty` built for the old ABI: Show terminal and CLI TUIs fail to start (dev or packed).
F2. The clipboard calls return Promises that are compared as strings: the GitHub-org paste is never detected, silently.
F3. The offscreen picture changes size or scale: clicks from the picture land off, or frames are the wrong size.
F4. The `electron` binary is missing when a check script or the packer spawns it.
F5. The preload bridge or IPC changes so `window.brain` is missing or a channel stops answering.
F6. The packed app fails signing, notarization or Gatekeeper because of new helpers or frameworks.
F7. A 0.1.137 install cannot auto-update to the new build.
F8. Something in the in-app browser (partitions, permissions, downloads, debugger input, protocol handlers, window-open handling) behaves differently.
F9. (review r1 #1) A teammate on macOS 12 auto-updates to a build Electron 44 cannot start on.
F10. (review r1 #3) A script the packed app runs as Node with `ELECTRON_RUN_AS_NODE=1` (the open guard, the browser MCP server, and Desk's mail and text helpers in `src/main/desk/`) no longer loads on Electron 44's Node.
